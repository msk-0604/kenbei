# 300社に向けた運用

月18,000円 × 300社（月540万円）を、少人数で回すための仕組みと手順。

## アプリ側でできていること

| 仕組み | 場所 | ねらい |
|---|---|---|
| 請求書払い（銀行振込・カード） | `/settings/billing` →「請求書で払う」 | カードを使わない建設会社を取りこぼさない |
| 運営ダッシュボード | `/ops`（`PLATFORM_ADMIN_EMAILS` の人だけ） | 連絡すべき会社（未払い・初期設定まだ・お試し終了間近・7日使われていない・解約予約）を毎朝見る |
| Excel 取り込み | `/kanri/import` | 名簿・現場一覧の手入力をなくし、最初の設定で止まらないようにする |
| はじめにやること | `/kanri` の上 | 5つの手順を終えるまで出し続ける。終わった会社は定着しやすい |
| 使い方・よくある質問 | `/help`（ログイン不要） | 問い合わせの前に自分で解決できるようにする。同じ質問が2回来たらここに足す |
| 業種別の工程候補 | `/kanri/presets` | 水道・管工事以外（電気・内装・外構・塗装・空調・解体・屋根）にも売れるようにする |
| 死活監視 | `/api/health` | アプリと DB が応答しているかを外から確認する |

## 本番で設定すること（一度だけ）

### Vercel の環境変数
- `PLATFORM_ADMIN_EMAILS`：運営画面を開ける人のメールアドレス（カンマ区切り）
- そのほか既存の Stripe・Supabase・VAPID の値

### Supabase
- 移行 `20261017120000_platform_org_overview.sql` を SQL Editor で実行する
- **Pro プランにする**（無料プランは毎日のバックアップがなく、使われない期間が続くと止まる）
- できれば PITR（いつの時点にも戻せるバックアップ）を付ける

### Stripe
- 設定 → 支払い方法 で **銀行振込（Bank transfers）** を有効にする。無効のままだと請求書払いはカードだけになる
- 設定 → Billing → 請求書 で「請求書を顧客にメールで送る」をオンにする
- 設定 → Billing → サブスクリプション で、未払いの請求書が期限を過ぎたら契約を「期日超過（past_due）」にする
  （→ `/ops` に「未払い」として出る）

### 死活監視
- UptimeRobot などで `https://app.kenbei.jp/api/health` を5分ごとに監視し、落ちたらメール・LINE に通知する
- Sentry のアラートを「新しいエラー」「1時間に50件以上」で通知するようにする

## 容量とお金の目安（300社）

写真は1枚 約250KB（長辺1400px の JPEG）。1社が1日30枚・月22日撮ると:

- 1社あたり 約165MB/月、300社で 約50GB/月、1年で 約600GB
- Supabase Pro はストレージ100GB込み、超えた分は1GBあたり数円ほど（料金は Supabase の料金ページで確かめること）
- 売上（月540万円）に比べて、インフラ代は月数万円の規模に収まる見込み

## サポートの回し方

- 窓口は `support@kenbei.jp` ひとつにまとめる。「会社名・画面・写真」を書いてもらう（`/help` に案内あり）
- 毎朝 `/ops` の「連絡する」を上から見て、電話かメールをする。電話で話すことは画面に書いてある
- 同じ質問が2回来たら `apps/web/src/features/help/help-content.ts` に足す
- 50社を超えたら、サポートの人（パート）か販売代理店を入れる。運営画面を見せるときは `PLATFORM_ADMIN_EMAILS` に足す

## 障害のとき

1. `/api/health` と Vercel・Supabase のステータスページで、どこが落ちているかを確かめる
2. 長引きそうなら、契約中の会社へメールで知らせる（`/ops` の「すべて」に連絡先がある）
3. 直ったら、原因と再発防止を `docs/decisions.md` に残す
