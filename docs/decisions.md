# 設計上の決定事項

実装前に固定する判断です。レビューで覆す場合は本ファイルを更新します。

| ID | 決定 | 理由 |
|----|------|------|
| D1 | 正式名称は KenSapo。Pro ブランドは使わない | 一般販売プロダクトそのもの |
| D2 | 既存 kensapo-alpha は参照のみ。スキーマもコピーしない | 記録SaaSの延長にしない |
| D3 | モノレポ（apps/web + packages） | 将来 Expo とドメイン共有 |
| D4 | 日報は一次入力ではない。キャプチャ確定から生成 | Zero Input |
| D5 | 写真フォルダをユーザーに作らせない | 自動分類 + 仮想ビュー |
| D6 | AIの出力は候補。低信頼度のみ確認 | 無条件確定しない |
| D7 | シグナルは推奨・注意・予測。自動実行しない | 人間が最終判断 |
| D8 | UIに「AI」を出さない | 結果がプロダクト |
| D9 | Branch / Department は NULL 可 | 零細に設定を強制しない |
| D10 | すべての業務テーブルに organization_id | テナント分離 |
| D11 | 論理削除 deleted_at | 監査と復旧 |
| D12 | 原価・粗利・工期は domain パッケージの純関数 | AIコストと再現性 |
| D13 | Importer は Graph の Repository だけを叩く | 通常DB処理と疎結合 |
| D14 | Similar Engine はインタフェース先行、MVPはルールスコア | 後から Embedding 置換 |
| D15 | 現場ホームは Today のみ。経営数値を出さない | ロール別情報 |
| D16 | 管理画面は「今確認すべきこと」が主、グラフの羅列ではない | 判断する仕組み |
| D17 | カスタムロールは Org 単位で追加可 | RBAC拡張 |
| D18 | 日本語 UI を第一言語とする | 国内建設業 |

## レビューで確認してほしい点

1. MVP の範囲（音声構造化を同期にするか、最初からジョブにするか）
2. 工種マスタをシステム共通にするか、Org 独自を主にするか（案: システム辞書 + Org 上書き）
3. 協力会社ユーザーの写真閲覧範囲（担当案件のみ、で進める）
