# kenbei-alpha（アルファ管工版）への寄せ方

kenbei-alpha で固まった仕様・UX・業務ルールに、KENBEI（多売版）を寄せた変更のまとめ。
元の仕様は kenbei-alpha の実装（`msk-0604/kenbei-alpha`）。

## 画面

| ルート | 内容 | 権限 |
|---|---|---|
| `/today` | ログイン後の最初の画面。日付切替・自分の予定／全員の予定・作業開始／終了・月カレンダー | 全員 |
| `/schedule` `/schedule/new` | 予定一覧（表形式＋カード）・予定の登録 | 閲覧は全員、登録は管理者 |
| `/sites` | 現場一覧（進行中／単発／完了済み／仮予定、今日の担当現場を上に） | 全員 |
| `/sites/new` | 現場登録 → そのまま作業工程を作る | 管理者 |
| `/sites/[id]` | 現場詳細（進捗％・写真・工程・人員・予定） | 全員（編集・人員は管理者） |
| `/sites/[id]/edit` | 現場の変更・削除 | 管理者 |
| `/sites/[id]/photos` | 写真の追加（既存のアップローダー） | 写真登録の権限 |
| `/sites/[id]/photos/gallery` → `/pdf?ids=` | 複数選択 → 印刷（A4・余白16mm・2列、ヘッダー等なし） | 全員 |
| `/sites/[id]/progress` | 作業工程チェックリスト（〇/△、楽観ロック、100%で「この現場を完了にする」） | 記録は作業員も、完了は管理者 |
| `/workers` `/workers/new` `/workers/[id]/edit` | 作業員名簿（アカウントを持たない人も登録できる） | 管理者 |
| `/kanri` | 管理ダッシュボード（alpha と同じリンク＋KENBEI 独自機能へのリンク） | 管理者 |
| `/kanri/schedules` `/kanri/archive` `/kanri/presets` | 全員の予定・完了現場の保存・よく使う工程の候補 | 管理者 |
| `/notices` | アプリ内お知らせ・通知のオン/オフ | 全員 |
| `/settings` | 通知・名前・合言葉（管理者）・会社情報・ログアウト | 全員 |
| `/settings/members` | 旧 `/settings`（招待・権限・ロゴ・契約） | org.manage / member.manage |

- 下部ナビは「スケジュール」「現場一覧」の2つだけ。管理者は右上の「管理」アイコンから `/kanri`。
- 日報・タスク・図面・チャットなど KENBEI 独自の機能は残し、現場詳細の「日報と記録を見る」（`/projects/[id]`）と `/kanri` から開く。
- `/projects` と `/projects/new` は `/sites` `/sites/new` へリダイレクト。

## 「管理者」と「作業員」

kenbei の RBAC はそのまま。alpha の「管理者」= `project.create` を持つロール（Owner / Executive / Manager / Office）。
DB では `auth_is_site_admin(org)`、画面では `isSiteAdmin(workspace)`。

## ログイン（両方に対応）

基本はメールアドレスとパスワード（スマホは顔認証・指紋＝パスキーも使える）。合言葉は会社が選んだときだけ使う
「かんたん」な方法で、ログイン画面と設定画面にセキュリティ面の注意書きを出す。会社は設定の
「作業員のログイン方法」で、合言葉ログインをやめる／決め直すことができる。

1. **メールアドレス**：これまでどおりの個人アカウント（招待・席数課金もそのまま）。
   顔認証は `user_passkeys`（公開鍵だけ）と `webauthn_challenges`（1回きり・5分）で、検証はサーバー（@simplewebauthn）
2. **合言葉**：alpha と同じ「会社の作業員合言葉」と「管理者の合言葉」
   - alpha は合言葉だけで会社を決めていたが、多売版では会社が多いので **会社コード（6桁）＋合言葉** にした。
     会社コードは初回だけ入力し、端末が覚える（招待メッセージの URL `?company=` でも入る）。
   - 合言葉は会社ごとに塩を付けた scrypt で `organization_passcodes`（サービスロールのみ）に保存。IP・会社コードごとに回数制限。
   - 作業員の合言葉を初めて設定すると、共通ログイン用のアカウントと `crew` ロールのメンバーシップを作る。
     `crew` は全現場を見られ（`project.read_all`）、写真・工程の記録ができる。**席数は1人分として数える。**
   - 管理者の合言葉は、設定した管理者本人のアカウントに紐づく。
   - 合言葉が漏れたときは、設定画面の「作業員の端末をすべてログアウトさせる」で共通ログインのセッションを消せる（`revoke_crew_sessions()`、サーバーのみ）。
     共通ログインの端末は画面を開くたびに Auth でセッションを確かめるので、画面からはすぐ締め出される。

共通ログインの端末では、alpha と同じく最初に名前を選ばせて端末（localStorage）に保存し、
「自分の予定」はその名前と予定の作業員名で照らし合わせる（表示の便宜で、セキュリティの境界ではない）。
個人アカウントでは、作業員名簿に紐づけたアカウント（または表示名）で判定する。

## 業務ルール

- **長期／単発**：単発＋着工日ありで登録すると、着工日〜完了予定日（なければ着工日だけ）の予定を1日1行で作る（最大60日、作業員は未割当）。長期は作らない。
- **completed_at**：完了以外→完了で今の時刻、完了→完了以外で消す。DB のトリガー（`projects_track_completed_at`）で決めるので、編集フォームと「この現場を完了にする」のどちらから変えても同じ。
- **お知らせ**：`post_org_notice()` が宛先を決める。本人には届かない／現場を見られる人だけ／`dedupe_key` で重複しない。
  唯一の例外は「現場が完了しました」で、完了させた管理者本人にも届く（`p_include_actor`、管理者だけが使える）。
  プッシュは Web Push（VAPID、`push_subscriptions`）と既存のスマホアプリ（Expo）の両方へ送る。
- **作業工程**：`mark` が正（`checked` / `status` は自動計算）。〇/△は `set_progress_mark()` だけで変えられ、`version` で衝突を検出（「ほかの人が先に更新しました」）。
  項目の追加・削除・並び替えは記録係（作業員を含む）もできるが、項目名の書き換えは管理者だけ（alpha の最新の動きと同じ）。
  共通ログインでは誰が押したか分からないので、端末で選んだ名前を `checked_by_name` と履歴に残す。
- **作業の開始／終了**：`record_schedule_work()`。予定を見られる人なら押せる。予定の登録・変更・削除は管理者だけ（RLS）。

## スマホアプリ（apps/mobile）

画面は作り直していない。お知らせのリンク（`/sites/:id` 以下）は、アプリでは現場画面として開く（`parseKenbeiRoute`）。

## alpha からの意図的な違い

- alpha で「既知の課題」だった **工程の候補のハードコード** は、会社ごとに編集できるようにした（`/kanri/presets`、`progress_item_presets`）。未登録の会社は alpha と同じ水道・管工事の標準候補。
- 合言葉ログインは会社コード付き・最低4文字（alpha は2文字）。
- 現場の状態は kenbei の5つ（仮予定・進行中・一時停止・完了・中止）を残し、フォームでは alpha と同じ3つを出す。
- 現場の削除は論理削除（予定・工程は消し、写真と日報の記録は残す）。
