# 運営の PDCA（毎週の見方と打ち手）

運営の画面は2つです。どちらも `PLATFORM_ADMIN_EMAILS` に入っている人だけが開けます。

| 画面 | 使い方 |
| --- | --- |
| `/ops`（運営） | 会社ごとの状態。「連絡する」に出た会社へ電話・メールする |
| `/ops/analytics`（分析） | 全体の数字。どこで止まっているか・伸びているかを見て、打ち手を決める |

運営の会社（代表のメールが `PLATFORM_ADMIN_EMAILS` に入っている会社＝自分たちのテスト）は、分析の数字に入れていません。

## 毎週月曜にやること（15分）

1. **Check（見る）**：`/ops/analytics` を開く
   - 「今週使った会社」が先週より増えたか
   - 「次に手を打つところ」に出た段（いちばん多く止まっている段）
   - 「機能ごとの利用」で、使われていない機能
2. **Act（決める）**：打ち手を **1つだけ** 決める（下の表）
3. **Plan / Do（やる）**：`/ops` の「連絡する」に出た会社へ連絡する。打ち手は1週間続ける
4. 翌週、同じ数字で効いたかを見る

## 段ごとの打ち手の例

| 止まっている段 | よくある理由 | 打ち手 |
| --- | --- | --- |
| 現場を登録 | 何から始めればいいか分からない | 登録した日に電話し、現場を1件いっしょに入れる |
| 作業員を登録 | 作業員にどう入ってもらうか分からない | 合言葉の決め方と、LINE で送る案内文を見せる |
| 予定を入れた | 予定を入れる意味が伝わっていない | 「明日の予定を入れると作業員のスマホに出ます」と案内 |
| 作業員がスマホで作業開始 | 作業員に案内が届いていない | 印刷用の案内（QR）を現場で配ってもらう |
| 日報を確定 | 日報を作るきっかけがない | 画面共有で日報の作り方（15分）を見せる |
| 契約 | 値段・払い方で迷う | お試し終了の3日前に、請求書払いも含めて案内 |

## 目安（最初の目標）

始めたばかりの数字はぶれます。10社を超えてから比べてください。

- 登録 → 現場を登録：8割
- 登録 → 作業員がスマホで作業開始：5割
- 登録 → 契約：3割
- 今週使った会社 ÷ 登録した会社：6割

## 数字の意味

- **訪問**：トップページなどに来た人（同じ人は1日1回）。`sales_funnel_events` の visit
- **使った会社**：その週に、予定・作業開始・写真・日報・タスク・チャットのどれかがあった会社
- **契約**：いま契約中か、一度でも支払いがあった会社
- 見本の現場（`source = 'sample'`）の予定は数えない

## 本番の DB に反映する（初回だけ）

分析画面は DB の集計関数を使います。本番の Supabase に、次のどちらかで反映してください。

- `supabase db push`（このリポジトリで）
- Supabase の SQL エディタに `supabase/migrations/20261021100000_platform_usage_analytics.sql` の中身を貼って実行

反映前は、分析画面に「DB の移行が未適用かもしれません」と出ます（ほかの画面には影響しません）。
